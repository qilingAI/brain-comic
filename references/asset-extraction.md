# 第二阶段：提取跨图资产并生成参考图

输入为用户选定的内容稿及其明确提供的角色素材。先通读所有画面，统计各对象实际出现在哪些图中，只为至少两张不同内容图共用的个人、群像、场景、道具另行设计并生成参考图，以保持跨图一致性；已有用户IP按下节直接导入。第二步包含资产提取、完整prompt拼接和所需参考图生成。只有用户明确要求调试或停在prompt时才不生图；正常执行第二步时不额外停下来要求确认。不在本阶段生成剧情逐张组合画面。

风格定义只维护在独立的 [styles.json](styles.json) 中，当前默认项为 `2d-chibi-comic`（2D Q版漫画）。主题只记录选中的 `style_id`；资产 description、跨图引用和类型版式不保存风格要求。最终 prompt 是按当前选择渲染的完整预览，不是新的风格定义来源。切换风格时重新拼接预览，保留资产 ID、实体外观与版式；不得残留旧风格的比例或排除词。配置项不存在时先提示选择有效风格，不静默换回默认值。

## 用户提供的角色参考

现成IP角色属于用户输入，优先于自动设计。先查看实际图片，识别用户指定的主体与不可改变的外观特征，再把角色绑定到 `C01` 等稳定ID。只指定部分人物时，仅替换这些ID，其余配角照常提取/生成；IP是动物、机器人或其他非人形角色时保留其物种和轮廓，不强行生成真人或加人类五官。

- **可直接用的原图直接复用。** 单张角色图、已有设定图或完整角色卡都可以，不要求用户补成固定白底/左右三视图后才能使用。多张资料时以用户指定主图为准；未指定时选最清晰完整、与当前造型一致的一张作为主参考，其他图用于核对。不要把不同角色/不同版本的造型擅自混合。
- 不为现成IP再走一次文生图设计；本阶段跳过这些人物的生成任务，仅生成缺少的其他资产。若确实需要整理新参考图，必须实际传入用户原图进行基于参考的生成，并保留原文件；按用户允许的范围改动。派生图经检查后明确导入为新的当前参考，不能用旧文生图任务覆盖原IP。
- 用户指定素材不受“自动提取需跨两张”的门槛限制，单次出场也可引用其输入原图；不因此生成一份单次人物设定图或给其虚增出场。`assets.md` 中标记为“用户提供，直接复用”，只记录真实出场图号。
- `description` 只记录从原图和用户文字确认的稳定外观，推测的背面或被遮挡细节不当作已知；固定身体比例或标志若属于IP辨识特征，可以作为身份约束，优先于默认Q版比例。配色、物种、衣服等变更以用户明确指示为准。
- 图中多名人物而用户未指明主体时先确认主体，不把群照直接绑定给某个未确定的角色。已经明确给出角色名称/分工时不反复询问。

导入主参考图（支持静态 PNG/JPEG/WebP，需要已有 Pillow，不调用生图）：

```sh
python3 scripts/image_jobs.py import-character --topic 主题目录 \
  --id C01 --name '用户IP名字' --source /用户/角色参考.png \
  --description '原图可确认的稳定外观' --lock '标志性配饰' --lock '固定的身体比例'
```

原图字节不经转绘地复制到主题 `images/assets/C01-provided.png`（按实际格式保留扩展名），同名时递增版本；清单记 `origin: "user_provided"`、`status: "provided"`、源文件名与哈希、当前相对路径、锁定特征。不把“用户提供”写成“已生成”。导入其他主题时重新复制，只使用用户明确指定的素材，不跨会话自动借角色。

每个角色分别导入，既可在空主题开始，也可替换该主题已有的某个角色ID，历史文件保留。替换后第三步旧引用的路径/哈希会失效，须重新编译受影响的画面；已经生成的旧人物画面不能只改清单就宣称换成新IP。`prepare --stage 2` 跳过已有用户IP，`prepare --stage 3` 会实际传入这些图片，并自动拼入高于默认画风的人物身份约束。Pillow只用于导入图片验证或参考输入打包，普通任务编译不依赖它。

## 先识别，再补足设计

- 以画面实际呈现为准，综合地点、出场人物、画面描述和对白指向，不只扫描名字。仅在旁白、简图标记或对话中被提及而未实际出场的对象，不建实体资产。
- 一个对象只建一条记录。名字、身份称呼、动作和机位变化不产生新资产；对同名但确实不同的对象，保留能说明区别的名字。
- **跨图出现是自动提取门槛。** 一个对象必须在至少两张不同的内容图中实际可见，才另行设计参考图。即使很重要、名字明确或承担关键说明，只出现一张也不自动入库，在该张描述中直接处理；用户指定角色原图按前节作为输入引用。
- 每项先列出去重后的出现图号，至少两个。同一张出现多个人、多个粮袋、多个视角，只算一张；一张参考图里的三视图或四宫格也不算跨图出现。
- 不因对白提到、地图上有标记、同属一个阵营或设计补全后可以加入别张，就虚增出现次数。实体被其他道具遮住、仅推定存在而未画出的情况也不算。关联物件各自计数，例如粮车出现，不等于粮袋也实际画出。
- 区分“原文依据”和“设计补全”。原文已规定的外貌、物件、空间关系必须保留。为使虚构漫画可绘制，可以补足少量脸型、发型、衣服颜色、材质和相对位置，并在审阅说明中明确哪些属于设计补全，不冒充正文已有信息。
- 不添加新人物、新阵营、精确历史朝代或剧情。不擅自推断真实人物的身份属性。无法确认且无绘制必要的字段直接省略；影响辨识的冲突单列待确认，不悄悄任选一种。

## 四类资产

### 个人

有独立身份的单个人物分别建档；若故事出现独立动物角色，仍独立建档并描述其物种外观，不强套人类衣服。只描述跨画面稳定的体貌、装束和配饰：

- 文本给出的身份和时代背景。
- 与绘制相关且已明确或已标注补全的年龄段、性别外观。
- 脸部轮廓、五官、稳定标记；发色、发型和整理方式。
- 体型、胖瘦与稳定体态。头身比、线稿、上色和渲染方式服从独立风格配置，不固定在人物描述中。
- 上装、下装、鞋履及固定配饰的颜色、材质、结构与区别。

不要把“勇敢、谨慎、熟悉守城”等性格当成可见外貌；不写当前情绪、视线、动作、手持物或镜头构图。手中反复出现的独立道具另建资产。

### 群像

无独立名字、以同类身份出现的多人合并为群像。“城头守军、搬粮守军、出击守军、留守守军”可能只是同一群体的不同任务，应统一衣着体系，不因此创建四套人。

不同阵营或服装体系明显不同的职业可分别建档。描述群体身份、共同服饰、配色、材质、体型与年龄构成；再给脸型、身高、发型等自然差异。群像成员不能长成主角的复制品。人数依内容需要，不凭空定义整支军队的精确规模。

不把一次的队列、搬运、冲锋、表情、伤势写成群体永久属性。不要要求所有工匠都穿甲、所有士兵都拿同一件武器；可更换的装备在相应道具记录中描述。

### 场景

按可复用的叙事空间建档，同一城门的门内、城头、门缝观察不因视角不同各建一处。空间确实不同或距离较远的地点分开建档；注明相互关系，避免后续出现互相矛盾的城内外方向。

description 用连贯一段说明室内/外、整体格局、主要地形建筑、地面材质、关键连接关系和主色。相对方位优先使用固定空间方向；不要把屏幕左/右在不同视角下当成永远不变。

仅描述固定空间；不包含人物、动物、临时动作、战斗特效或可搬走的独立道具。城墙、城门、固定木栅属于场景；粮袋、粮车、图纸等另属道具。光照和天气如果不是该空间的身份特征，不在此锁死。

### 道具

仅保留实际跨越至少两张内容图的物件，描述品类、轮廓、材质、颜色、组成结构、磨损及识别特征。成套物件如弓与配套箭矢可合为一条；同物的不同角度、开合与拿放状态不拆分。不能仅因“是关键道具”就豁免跨图门槛。

正文明确的结构和状态要保留，例如未组装完成的攻城车不能改成已完成战车。与建筑不可分的部分不重复建道具；简图上的“援军”旗记是图纸内容，不额外提取一支已到场的援军。未规定的文字不补写真实朝代徽记、品牌或引文。

## 输出与复核

### 完整 prompt 的拼接规则

每项最终 prompt 由“styles.json 中选定项的 prompt → 类型版式 → 资产描述标题 → 完整 description”组成；不得残留占位符或“同上、见某项”等省略。此文件只维护与风格无关的类型版式，不复制具体风格正文；风格要求与版式要求保持独立。

个人使用下方前缀，随后加 `角色描述：` 和该角色完整 description。这里的左右分区是构图布局，不是画一条竖线；右侧三个视图之间也不画分割线。

<!-- C_PREFIX -->
```text
生成同一角色的外观设定参考图，画幅16:9。纯白至极浅灰的无缝背景，无环境元素、无墙角和地平线，仅保留浅接触阴影。左侧约40%宽度为角色胸部以上的正面平视特写，清晰展示脸部、发型及上身服饰细节；右侧约60%宽度依次展示同一角色的正面全身、侧面全身、背面全身。右侧各视图等高，头部和脚底对齐，服装、发型、配饰和颜色保持一致，姿态自然中性，手部不要遮挡主要服饰，不持剧情道具。左右两区及三视图之间不画分割线，不裁切头脚，不输出标题、视图标签、水印或对白。
```

群像使用下方前缀，随后加 `群像描述：` 和完整 description。群像不套个人的40%/60%布局或三视图；参考图中的少量示例人物不等于剧情内整支部队的人数。

<!-- G_PREFIX -->
```text
生成同一群体的外观参考图，白色无缝背景，无环境元素，仅保留浅接触阴影。以多名代表成员的完整全身展示共同的服装体系与自然个体差异，姿态自然中性，人物之间保留间距，不相互遮挡，不裁切头脚。不要重复复制同一张脸，不混入有独立身份的主角，不表现战斗或剧情动作，不固定手持剧情道具。不使用单人特写加三视图的左右布局，不输出标题、文字标签、水印或对白。
```

场景使用下方前缀，随后加 `场景描述：` 和完整 description。场景展示完整环境，不套白底抠图；四格是同一地点的不同观察方向，不能变成四个不同场景。

<!-- S_PREFIX -->
```text
生成四宫格场景参考图，展示同一个场景的四个不同视角。左上为正视图，右上为俯视图，左下为背视图，右下为侧视图。四个画面保持相同的空间布局、建筑结构、材质、色调、光照和时间状态，不镜像翻转固定方位；直线建筑保持笔直，不使用鱼眼、球面或小行星畸变。仅展示静态空间及其固定建筑陈设，不出现人物、动物、车辆、可移动道具或剧情动作，不出现战斗、火焰、技能和特效。保留场景本身的地面、墙体、室内外环境，不使用白底抠图。不输出任何文字、视图标签、对白或水印。
```

道具使用下方前缀，随后加 `道具描述：` 和完整 description。保持源项目道具直接展示的思路，不擅自要求每件道具也出四宫格。白底与展示约束是本项目的补充。

<!-- P_PREFIX -->
```text
生成该道具的独立外观参考图，白色无缝背景，仅保留浅接触阴影。完整展示道具轮廓、材质和关键结构，选择能看清主要部件的自然展示角度，不裁切，不出现人物、手部或无关环境。成套物品可一同展示，保持各部件配套关系；保留描述中的未完成状态，不加入剧情动作或特效。不套人物三视图或场景四宫格。不添加标题、视图标签、对白、水印或描述未要求的文字；物件自身明确要求的文字按道具描述保留。
```

交付一个主题内的 `assets.md`，包含：

1. 来源内容文件、选中的 `style_id` 及风格配置链接。
2. 简短的设计补全说明；没有补全时写无。
3. 四类跨图资产。每条记录含稳定 ID、名称、原文依据/别名、去重后的出现图号、资产自身描述，以及可直接复制的“最终生成提示词”完整文本块。用 `C01` 表示个人、`G01` 表示群像、`S01` 表示场景、`P01` 表示道具。修订时保留仍在使用的 ID，不因剔除单张元素而重排其他 ID。
4. 每张画面引用的跨图资产 ID，以及不入库的单张元素简表。单张元素直接描述，不补分配参考图 ID，不在此写组合后的画面 prompt。

description 只保存外观，不夹带依据、待确认说明、风格、版式、文件路径、对白或剧情摘要。自动设计资产的最终生成提示词必须完整拼入风格与对应类型版式；用户IP记录“直接复用原图，无生成任务”及实际文件。依据与补全说明不进入最终 prompt。

复核画面 1 到 N：每项自动提取资产至少有两个不同且可信的出现图号；用户IP按真实出场图号复用输入，不虚增。其他单张元素没有残留在资产库、最终参考图 prompt 或跨图 ID 中。所有需要画出的内容可归入“资产引用”或“该张局部描述”；别名已合并，群像不因换任务重复建档，场景与道具不重复。逐项检查自动生成 prompt 的风格来自本主题配置，个人有白底、16:9、左40%特写/右60%正侧背三视图、无分割线；场景四宫格视角与空间一致、不被白底覆盖；群像和道具未误套版式。用户原图不强制重排版；检查锁定特征与实际参考一致。只检查描述字段，不等于检查了最终 prompt。

## 生成与落盘

已导入的用户IP直接复用。对剩余需要生成的资产，按 SKILL.md 的生图能力选择先检查API凭证，无配置时使用宿主生图技能和实际工具；宿主无工具时走器灵浏览器授权通道。每项自动设计资产单独生成一张参考图，不把多个资产拼成一张目录总图。使用本阶段已拼接的完整prompt；个人遵守左右特写与三视图版式，场景遵守四宫格，群像与道具遵守各自白底版式。

任务准备与第三步共用 `scripts/image_jobs.py prepare --stage 2 --topic 主题目录`，跳过用户IP，其他文生图任务输出统一结构和空的reference_images；生成结果用同一脚本的record保存到资产清单。全部素材已有时任务数组可以为空，不为凑任务重画角色。调用工具或API的代码不在两步各写一套。

生成图片先经 `record` 保存到主题 `images/candidates/assets/`，版本后缀只用于工作区。检查实际图片后可在记录时传 `--review passed`；未通过用 `--review needs_revision` 进入 `images/not-selected/assets/`。更新 `images/manifest.json` 的当前图片、prompt、style_id、途径和检查状态；结果不明时不自动重复请求。

本阶段素材全部可用后执行 `python3 scripts/image_jobs.py finalize --stage 2 --topic 主题目录`。通过检查的资产和用户提供角色移动到 `images/assets/`，命名为 `C01-角色名.png`、`S01-场景名.png` 等；未采用旧版移到 `images/not-selected/assets/`。同步清单、已有第三步绑定和预览中的路径，原图内容与哈希不变，历史来源可追溯；不在最终资产目录并排放多个版本。

查看实际输出，检查画风、身份、服饰、布局及场景/道具结构；有明显偏差时进行针对性修正，不为了凑齐数量将错误图片作为成功产物。后续需要一致性时实际引用这些图片，而不只传描述。最终交付图片预览、保存位置、清单与未解决的问题。只要求调试prompt的当次任务可以跳过本节，不调用图片或视频工具。

## 版式来源

个人与场景版式借鉴 shengshimedia 的角色特写/三视图和场景四视角拼接方法，再补充群像与道具模板。所需前缀和拼接规则已完整收录于本技能，无需访问原工程；人物描述、画风和展示版式分别维护。
